## Synthetic control checks, not a model context limit

The definition's 65,536-byte cap, 4,096-byte output reserve and 256-byte safety
margin are shared **toy UTF-8 apparatus units**, not a token ceiling or a live
H treatment. For a joint-cap fixture, subtract output reserve and safety once;
for an input-only fixture, do not subtract output reserve from input again.
Measure the complete envelope, including fixed contracts, retained state and
wrappers. The source allowance is the remaining capacity after the empty-source
envelope and applicable reserves. Refuse overflow intact; do not truncate.

A small in-memory whole-file fixture demonstrates only these properties:

- unknown/ineligible paths cannot be read;
- a read of resident, unchanged content may return a reference only while the
  actual content remains in the assembled request;
- explicit eviction/clearing requires full content and a new exposure charge
  on reread; a pointer is not memory;
- changed content at the same path invalidates the old resident version;
- failed budget admission does not mutate residence or count unreturned bytes;
- exact-limit, one-byte-over, Unicode, fixed-overhead and reserve-convention
  checks use the actual serializer, with no model/provider behavior inferred.

This is not an operational retriever, summarizer, tool API, persistent memory
service or native-client modification. No automatic compaction, indexed search,
language-service advantage, large corpus or compatibility matrix is introduced.

### Engineering corrections before publication

The initial prototype incorrectly used cumulative source exposure as resident
capacity. Separate AI-session review rejected it: an eviction must free resident
space even though a later full reread adds another exposure charge. Admission now
uses the fully serialized prospective resident request; cumulative exposure is
an independent historical counter. This is an apparatus correction, not a new
scientific treatment or a reason to discard an experimental observation.

The first two focused validation attempts (`results/h0-validation-01/` and
`results/h0-validation-02/`, retained locally) each passed four shallow tests and
produced four envelopes. They did **not** establish H0 acceptance. Review also
required explicit contract-content pins, population-separated accounting, actual
empty-envelope overhead, refusal with existing resident content and expanded
regression coverage. These deficiencies and the earlier validation outputs are
retained rather than described as successful end-to-end evidence. There were no
candidate calls or credentials in either attempt.

Validation 03 expanded to 14 tests and failed three: a test/control attempted to
demonstrate cumulative exposure beyond an 80-byte request cap with only four
one-byte reads. The implementation correctly admitted the reads; the witness
was insufficient. The correction derives enough eviction/reread iterations from
the serialized cap. The retained `results/h0-validation-03/` failure is distinct
from the earlier capacity bug. Its CLI and later checks did not run after the
test failure. A focused repair also removes the remaining mixed-population
accounting and adds CLI byte/overwrite regression checks.

E3a packet verification is model-free; it does not run a pilot or consume a live
