## Construction and integration obligations

S137 factors recursive syntax into signature functors, a fixed point and selected sums. S138 develops reusable algebras, transformations, annotations, queries, substitution, monadic traversals, mutually recursive families and GADTs over that representation. Distinct signatures can encode phase boundaries: desugaring returns a core syntax that excludes sugar; evaluation can return a value signature instead of the whole expression language. Signature constraints, injection/projection instances and intermediate type annotations remain explicit integration work. The initial partial evaluator is subsequently adapted to report errors through `Maybe`; the output signature alone does not establish all intended semantics.

Ordinary algebras receive already processed children in a carrier type. A transformation whose result is another syntax tree entangles that carrier with its target signature. It also obscures which result nodes were newly constructed and which came from children. A natural transformation producing only one output constructor is too restrictive for useful desugaring.

S138 therefore represents contexts with holes and uses a rank-2 term homomorphism of shape `forall a. f a -> Context g a`. It can construct a context around opaque child placeholders, copy, omit or rearrange them, but cannot inspect their arbitrary values under the intended parametric interpretation. The recursive application fills those holes with processed child trees. Desugaring fits this form; evaluation that inspects child results generally does not. The printed `Swap` transformation itself duplicates a child placeholder.

Contexts and terms share a GADT representation with a phantom parameter restricting the `Hole` constructor. A closed term cannot contain a hole. The implementation uses `unsafeCoerce` for the representation-preserving conversion from a closed term to a context, avoiding a traversal; that argument depends on the stated representation invariant. It is not a blanket safety theorem for arbitrary unsafe casts. The earlier fixed-point isomorphism also has an explicit strictness proviso in the paper. Infinite/partial Haskell values and the intended finite total algebraic model must not be silently identified.

Annotations can be stripped before an existing computation, supplied through `Reader`, or distributed across a sum. These alternatives need different classes/instances. Contexts make annotation propagation more precise: annotate freshly constructed output nodes with the current input node's annotation, while copied subtrees keep their earlier provenance. A general opaque tree-returning function does not provide this distinction automatically.

For mutually recursive families, an index records the sort and higher-order functors replace ordinary functors. GADT constructors then constrain input and result indices, including nested pairs. These indices establish the encoded sorting invariant, not every semantic precondition of an extensible evaluator. Generic class and smart-constructor generation reduces repeated declarations; usability and maintenance benefit are not measured. Full case analysis over an extensible remainder remains future work in this paper, motivating the later composing/decomposing method rather than treating that method as already present in 2011.

## Fusion: preserve effects as well as output trees

For pure finite transformations, composing a homomorphism with another homomorphism or algebra can avoid intermediate traversals/trees. GHC rewrite rules automate selected forms. Monadic folds introduce an explicit `Traversable` sequencing policy; effect order and occurrence count are now part of the result.

Section 4.4.3, printed p. 90/PDF p. 8, acknowledges that general monadic fusion fails, invokes a distributivity condition attributed to Fokkinga, gives `Maybe` as an example, and additionally claims sufficiency when either stage is pure. Those statements need a stronger boundary for the displayed bottom-up definitions. The following are **our finite symbolic reconstructions**, not author experiments or an executed counterexample suite. Write `H` for the recursive bottom-up application, with holes returned without effects, and compose local steps by `f ⋆ g = H(f) <=< g`.

| Case | Sequential `H(g)` then `H(f)` | Fused `H(f ⋆ g)` |
| --- | --- | --- |
| Pure `g` maps a leaf to a leaf and `Unary(x)` to `Pair(Hole x,Hole x)`; `f` preserves every output constructor and emits one Writer count per constructor; input `Unary(Leaf)` | Output `Pair(Leaf,Leaf)`, count 3 | Same output, count 2: the original child is processed once and its already produced result is duplicated |
| Pure `g` maps source `Leaf` to target `Bad` and discards the child of `Unary(x)` by returning target `Good`; `f(Bad)` fails in `Maybe`, while `f(Good)` succeeds; same input | Desugaring produces `Good`; later traversal succeeds | Processing the original child fails before the parent can discard it |

Both transformations fit the allowed opaque-hole representation. Nonempty output contexts do not prevent either case. Thus purity of the first stage alone does not establish the displayed equation, and the name `Maybe` alone does not establish it for arbitrary deleting homomorphisms. The first case does not require effect-order sensitivity: a commutative count still changes. A sufficient law must account for the actual transformations and sequencing, including discarded and duplicated work. The now-complete [S140 reading](S140-monadic-maps-folds.md) resolves its exact hypotheses: a lawful Kleisli lifting plus a transformation-specific homomorphism/naturality condition. These cases do not refute that conditional theorem; pure-function naturality or a monad name does not establish the missing condition.

The [dated implementation](https://github.com/pa-ba/compdata/blob/766705f0048469e05fb3ebba13ce57217cb660d8/src/Data/Comp/Algebra.hs) importantly distinguishes several traversals. `appHomM` is bottom-up (lines 331–338); `compHomM` applies the second traversal to the first local context (387–390). The generic pure-first rule uses the different `appHomHomM` traversal (643–651, 849–850), which follows generated contexts and their holes instead of processing every original child once in advance. The first counterexample must not be attributed to that different rule. The source also contains the bottom-up `Maybe` composition equation (825–826), to which the deletion example is relevant as a rule specification. Actual rule firing, compiler behavior and current library behavior were not tested. The current Hackage release is a later edition and is not substituted for the dated source.

Futumorphisms are another separate boundary. Requiring each step to produce a nonempty constructor context supports productivity under the relevant totality assumptions; the generalized form can emit only a hole and lose that guarantee. This is not an argument that arbitrary recursive source transformations terminate.

For Nu's interactive state/effects claims, the implication is concrete: equal returned structures do not certify equal event, I/O or state behavior. A fusion or scheduling optimization needs its own effect-preservation argument. Pure descriptions and typed syntax remain useful mechanisms with explicit interpreter obligations.

## Runtime evidence and the author's correction

The paper compares eighteen operation variants with ordinary recursive algebraic-datatype implementations. Table 1 normalizes by the corresponding ordinary implementation, so values below one favor the compositional form. Inputs are one handwritten 16-node expression and randomly generated expressions of depth 10 (about 800 nodes) and depth 20 (about 200,000). Four composition rows also show unfused values in parentheses: 66 published ratios altogether. The stated environment uses GHC 7.0.2 with `-O2` and Criterion. The discussion reports sensitivity to older GHC 6.12. Exact random seeds, repeated-workload sampling, confidence intervals and a fully pinned measurement environment are not supplied by the article.

The original desugaring ratios include 0.0000061 and 0.0000053 for the largest input, apparently implying more than five orders of magnitude improvement. They must **not** support the survey's performance conclusion. In [author commit `22f9b52147c054f2e394df5d02d2760679641432`](https://github.com/pa-ba/compdata/commit/22f9b52147c054f2e394df5d02d2760679641432), dated 2013-06-02, Bahr explicitly identifies a faulty `NFDataF` generator as the cause of those WGP 2011 desugaring results. The inspected 2011 generator omits fields having the functor-argument type, while `rnf (Term x)` delegates directly to that shallow operation. Consequently the nominal `nf` benchmark does not force the compositional output's recursive children. The correction changes generated patterns and `rnf` calls to include all fields. This is primary author-confirmed evidence, beyond an inference from suspicious ratios.

The author states that rerunning affected only the two desugaring benchmarks. Preserve that as an **author-reported scope check**, not an independently established guarantee about every result. A neighboring [benchmark commit](https://github.com/pa-ba/compdata/commit/f4ba879a61911970f2a1e3bf8f4628b9384c02e5) also changes `getStdGen` to `newStdGen`. The later measurements use different input sizes, so original and corrected numbers cannot be treated as paired observations isolating one code change.

The inspected benchmark configuration uses `-DNO_RULES` and separately named fused/unfused functions. Consequently the reported comparison is not evidence that the compiler automatically fired a particular rewrite rule, including the monadic rule discussed above.

The [corrected results release](https://github.com/pa-ba/compdata/commit/2236edaa2575333b59b2bb704615ab58f592f93a) contains `benchmark-results/results-corrected.xlsx`. Its one sheet, `results.csv`, places aligned means in B/D/F/H and normalized ratios in C/E/G/I. Row labels remaining in A35:A133 have no separate measurements: do not count them again. The 33 measured implementations/baselines across four inputs give 132 means and 88 normalized formulas. All 88 cached ratios agree with independently computed divisions to relative tolerance `1e-12`.

These figures are rounded from author data, not measured locally. Corrected desugaring is slower than the ordinary datatype in every displayed case. Nevertheless all sixteen within-compositional comparisons of an unfused and fused two-stage operation favor fusion: computed ratios range from 1.412 to 2.411. That useful optimization does not establish superiority over the ordinary baseline. Monadic inference without desugaring is slightly faster on the first two inputs (0.941 and 0.891) and slower on the larger ones (1.151 and 1.685); generic-query results and direct-recursion comparisons are also task dependent. Preserve favorable and adverse cases rather than replacing the whole dataset with a single overhead verdict.

The 2011 ODS variants, current Hackage package, 2013 corrected workbook and S139's different 2016 evaluator are separate evidence objects. The corrected workbook supplies means and formulas, not per-sample observations or a recorded exact machine/compiler/seed configuration. No statistical equivalence, allocation decomposition, developer-effort estimate, live-game latency result or independent replication follows.
