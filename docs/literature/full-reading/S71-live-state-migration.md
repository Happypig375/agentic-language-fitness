## Mechanism and assumptions

Sections 2–3 represent a live program with explicit state and an effectful step function. The state is existentially packaged with a `Data` constraint so a running program can be replaced by a differently typed one. Generic migration examines constructor/field structure, retains compatible old data, initializes additions from the new program's defaults and permits custom conversions. Named fields can distinguish values with the same type. Renaming, deleting or reorganizing state therefore creates correspondence/default obligations; a snapshot alone supplies no interpretation of the new schema.

Functions cannot satisfy the required generic state representation and must reside in the step function. This is a restriction on the representation of persistent runtime state, not a guarantee that all effects or external resources have become data. An MVar loop, foreign-store and GHCi/ghcid support reloading. A visitor-count web server and an oscillator illustrate retained state across code edits. These are capability demonstrations, without an independent user comparison, runtime benchmark or maintenance experiment.

Section 4 composes effectful Mealy-style cells. Their product state, plus explicit control state where needed, lets components be combined without hand-authoring one global state datatype. Optional sensor/pure-signal/actuator separation and monad transformations organize effects; they do not establish replay or rollback of an external world. The oscillator uses an assumed fixed stepping rate. Richer clock integration is future work, so the examples do not establish fidelity under game-frame jitter or mixed clocks.

## Consequential adverse cases and supplement limits

- **Type correctness does not establish semantic migration validity.** Section 7, PDF page 12, explicitly limits generic migration to producing a state with the required type. Application invariants outside that type can be violated. Defaults that type-check may still contradict new gameplay rules, existing entities or external resources.
- **Type-checking does not prevent every control failure.** The naive recursive exception-cell example in section 5.3 hangs while initializing. The paper supplies a dedicated looping operator. The appendix also warns that a strict self-dependent `ArrowLoop` can fail at runtime; delayed feedback is a different construction.
- **The representation trades expressive power for migratable state.** Appendix section 2 shows cells are less general than Dunai's monadic stream functions because higher-order state cannot meet the `Data` constraint. The main paper's monadic control-flow presentation needs the appendix's qualification: the construction permits finite, nonrecursive algebraic exception types at the `Try` boundary. It does not provide unrestricted higher-order switching. Computation inside the monadic context can still involve other types.
- **Costs remain open.** The paper retains responsibility for space leaks with users and warns that per-sample debugger I/O can be costly. It supplies no allocation, latency or retention measurements from which to infer a net runtime benefit. Integrating real frameworks' event loops beyond the toy examples remains future work.

The printed examples also need care before executable reuse. On PDF page 4, the illustrative foreground loop recurses with its original program rather than the returned updated value; Figure 1's MVar version does thread updated state. This is a verified printed-example discrepancy, not a tested defect in the released library. No construction or experiment was launched to resolve it.

## Testing is an additional obligation

Section 6 embeds cells over finite input lists and demonstrates QuickCheck properties, then logs migration checks in a Writer effect. A test instance can be reloaded before the production instance. This is a concrete way to test proposed migrated state; it is not a proof over every reachable state, edit or external interaction. The illustrative hundred passing tests do not establish complete oracle sensitivity or a migration success rate. State samples, invariants, effects, clocks and the correspondence between test and production instances would need explicit coverage.
