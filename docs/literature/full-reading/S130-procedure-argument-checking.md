## What the comparison changes

The live B02/B10/B12 gap after S127–S129 is the contribution of checking when type information is already available. This study compares K&R C under SunOS4.1.3 `cc -c -g` with ANSI C under GCC2.7.0 and the stated `-ansi -pedantic -W -Wimplicit -Wreturn-type` flags. The package Makefile preserves these commands. Both arms receive the same raw wrapper header: `_A_(l)` expands to the prototype under `__STDC__`, and to `()` otherwise. Human-readable signature text remains in the supplied file and common manual, including parameter names, types and meanings. Thus the contrast is narrower than removing all type names and checking together, although compiler implementation/messages and compilation behavior also differ. The authors judge the other messages comparable; they do not experimentally isolate that judgement.

The shared Motif wrapper replaces variable argument lists with checkable fixed signatures and introduces resource-name types, while adding convenience operations. Its increased checkability is part of the selected setting, not an independent comparison against ordinary Motif. The two GUI tasks are a 2×2 matrix inverter and a file browser. Subjects receive declarations, initialization, algorithmic structure and pseudocode for the missing calls, plus tailored documentation and runnable gold programs. The solution appendices contain sixteen and eleven functional units (FUs). Subjects choose functions/arguments; few implementation variations are expected. There are no example *programs* in the documentation, although the package's manual does contain example calls. Do not describe this as broad algorithm design, undocumented programming, or a static-versus-dynamic runtime comparison.

Forty unpaid volunteers entered; six were excluded: one deleted protocols, one took nearly ten times as long and was deemed insufficiently experienced, and four attempted only one task. The retained34 comprise two postdocs, twenty CS PhD students (one with a physics master's), and twelve CS graduate students. Mean programming experience is ten years; experience with the relevant GUI library is limited. Random allocation crosses task order and compiler order across four groups, with each retained person doing both tasks under different compilers. Initial learning therefore precedes a different task and compiler; familiarity is not separately randomized or directly measured as comprehension.

Subjects were advised to spend roughly an hour per problem, with **no enforced time limit**, and could deliver incomplete or nonoperational programs. Time means time to delivery, not time to verified correctness. Pauses over ten minutes were manually subtracted. The paper records40 entrants/34 analyzed people, rather than treating the abstract's40 as the complete-case denominator. The extreme-time and incomplete-pair exclusions limit intention-to-treat interpretation; omitted outcomes cannot be reconstructed from the package.

## Outcomes and preserved results

One annotator assigned defect identities to successive compilation snapshots. Automated consistency checks and some manual checking found about4% annotation mistakes; the paper calls this negligible, but it is not independent annotation agreement. Compiler/linker errors common to both conditions, minor behavioral deviations and undetectable invisible defects are omitted from the main defect endpoint. The retained categories are severe behavioral defects, severe defects detectable by ANSI argument checking (`severeD`), and behaviorally invisible but ANSI-detectable defects (`invisD`). Consequently “total remaining defects” means this selected taxonomy, not all incorrect behavior.

Reported medians and rank-sum p-values below are transcribed from Tables2–4. Each task-position column pools both task identities; the combined column contains both attempts from every retained person. The paper uses interpolated quantiles and 75th/90th percentiles for mostly-zero variables.

| Endpoint, ANSI / K&R | Both tasks | First task | Second task |
| --- | --- | --- | --- |
| Delivery hours | 1.3 / 1.35; p=.49 | 1.6 / 1.6; p=.83 | .9 / 1.3; p=.018 |
| Compiled versions | 15 / 16; p=.84 | 19 / 21; p=.63 | 12.5 / 13; p=.16 |
| FUs/hour | 8.6 / 9.7; p=.93 | 7.2 / 8.5; p=.31 | 12.8 / 10.7; p=.061 |
| Accumulated detectable severe-defect hours | .3 / 1.2; p=.004 | .5 / 2.1; p=.028 | .2 / 1.1; p=.059 |
| Remaining selected defects | 1 / 2; p=.016 | 1 / 2; p=.32 | 1 / 2; p=.031 |
| Remaining `severeD` defects | 0 / 1; p=.0001 | 0 / 1; p=.015 | 0 / 1; p=.0022 |

The checking condition retains a clear favorable pattern for detectable residual defects, including both task positions. Total selected residual defects favor ANSI overall and in the second task. Non-detectable severe-defect medians are1/1 overall, with p=.66; this is not equivalence. The90th-percentile `invisD` result favors ANSI overall and initially, not significantly on the second task. Reintroduced-defect75th-percentile counts favor ANSI on the second task (0/1, p=.009); the proposed reduction in trial-and-error is an explanation, not measured mediation.

Timing favors ANSI on the second task, without an established pooled or first-task timing difference. The second-task FU-rate median is about20% higher, but p=.061 exceeds the paper's stated .05 criterion despite its “weakly significant” description. Likewise second-task accumulated defect time p=.059 is not below .05; the pooled and first-task comparisons do pass that threshold. Do not convert nonsignificance into no effect or promote the abstract's learning narrative into a tested causal interaction.

The prose's p-value gloss as a probability of equal medians is incorrect. A rank-sum test is not generally a test only of medians; the pooled compiler groups also contain paired attempts from the same people, which the reported rank-sum analysis does not model. Multiple endpoints/subgroups and selected tasks further limit an unqualified causal or universal effect. These concerns qualify inference while preserving the observed positive defect and second-task timing patterns.

## What the recovered package verifies—and leaves unresolved

All **68 rows ×39 columns** of `AB.data` were parsed, with34 distinct subjects, two task identities and both compiler codes per person. All68 remaining-defect sums and all68 reintroduced-defect sums agree exactly with their three class components. Compiler-wide delivery/version/defect medians reproduce the printed combined summaries. `life5`, the severe detectable class, reproduces all six printed lifetime medians; Figure6 labels this class, while the prose calls the statistic interface-defect lifetime more broadly. It is not accumulated time for every defect category or independently observed debugging effort.

The supplied data retain `severeD` defects in4/34 ANSI deliveries and20/34 K&R deliveries; `invisD` occurs in0/34 and4/34. These are descriptive counts from the package's selected taxonomy, not independent rescoring of original programs. Non-detectable severe defects remain in both conditions. Compiler acceptance is therefore not the endpoint or a certificate of intended GUI behavior.

There are material correspondence limits. The package's group counts are8/11/7/8, whereas paper Table1 prints8/11/8/7. The instruction macros independently confirm the four group meanings, so no silent group relabeling is adopted. Ordinary phase medians for compiled versions are18/21 initially and12/15 second, versus the paper's19/21 and12.5/13. Time/lifetime/residual median directions above survive the package check, but exact phase-summary equivalence is unconfirmed. Rounded hours and unavailable original analysis/quantile settings also prevent an exact FU-rate reproduction. The package's evaluation notes mention several small changes to handouts and early run-marker problems; these reinforce its stated version/trace limitations. No replacement dataset or corrected inferential result is invented.

A consequential endpoint limit is resolved directly in the supplied `protcount` output routine: FU productivity is `(gold FUs − gaps) / hours`. `Evaluation` explicitly defines gaps as *unattempted* functionality, distinct from attempted but faulty functionality. That routine does not subtract defective implemented calls. Thus the package computes an attempted-unit rate adjusted for omissions, whereas the paper initially describes complete/correct units. This rate cannot by itself mean correct behavior delivered per hour. Quality is measured separately through the retained defect taxonomy. The paper's favorable quality evidence remains; future comparisons should keep attempted work, correct behavior and time distinct.

## Implications and follow-up

S130 supplies direct prior evidence for useful argument-checking feedback **with signatures and documentation held available**, narrowing the mechanism gap left by S127's names-only intervention. It is stronger evidence for that scoped benefit than a cross-study difference between type-name papers. It does not identify a universal checker increment: wrapper design, two compiler implementations, initial learning, selected library-call tasks, exclusions and source-version limits remain. It does not test F# case enumeration, fallback matches, Nu architecture, agent context savings or state-evolution behavior.

For the background synthesis, connect checkability to the actual fault class and independent behavioral obligation. A callback's type-correct signature does not guarantee the right event, object or effect; the study itself counts non-type defects. Intended D1 outcomes must retain old/new behavior and all assigned attempts, without treating a diagnostic count, attempted-unit rate or faster delivery of an incomplete program as success.

The full bibliography was examined. Gannon1977's data-type-convention comparison and Basili–Perricone's interface-defect distribution remain conditional primary-method leads; their quoted claims here are only S130's characterization. The unpublished Mesa anecdote is not controlled evidence. The earlier conference/report lineage remains to be compared if an edition-specific claim requires it. S131's deliberately contrary task design is still access-limited; S132's scanner/parser PDF is acquired at opening-only coverage. Acquired coverage-checker and Join Token methods remain consequential alongside them. No theme is declared surveyed from this one mechanism comparison.

**Unique:** unresolved; checking with information retained has a direct predecessor. **Valuable:** selected human defect and later-task timing benefits are concrete, but population prevalence, full net cost and Nu/agent transfer remain unmeasured. **Scientifically valid:** the intervention and endpoint distinction are reconstructed, with bounded package corroboration and unresolved phase/edition correspondence; ISE feasibility remains unvalidated. All experimental holds remain.
