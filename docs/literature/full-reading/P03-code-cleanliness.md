## Construction and actual contrast

The study holds the agent and task fixed while varying a bundle called cleanliness: SonarQube issue/complexity properties, helper factoring, naming, duplication and comments. It intends to preserve architecture/dependencies/external behavior, but operational parity means passing finite suites, sometimes adjusted for internal refactoring (pp. 2-3). Slopify builds and explores before transformation, rejects test-breaking degradation; Vibeclean builds then addresses analyzer-localized issues. Some transformations merge modules, inline or extract helpers and persistence responsibilities; therefore this is substantially closer prior art than a formatting intervention (p. 3). It is not a clean isolation of one architectural mechanism.

Six selected pairs comprise three primarily Java and three primarily Python repositories; all three private SonarSource pairs use Slopify and all three public pairs use Vibeclean (pp. 3-4, table 1). Direction, provenance and transformation shape are consequently bundled. Thirty-three author-curated tasks are selected using pair differences and hotspot maps: 13 cognitive-hotspot, 14 multi-module and six insensitive calibration tasks (pp. 4-5). Tasks avoid internal edit-location hints; hidden tests call the public interface. References must pass both variants and untouched versions must fail the new-task suite. Two unsuccessful construction iterations lead to hand rewriting or dropping. This is purposeful sensitivity sampling, not an independent random maintenance population.

## Agent, information and scoring

Claude Code/default tools with Sonnet 4.6 runs ten repeats per task/side: `33*2*10=660` trials (p. 5). The task is blind to condition labels; each container has matching dependencies/services except its source tree. Agents can navigate, edit and use the normal tools, including subagents. CPU/memory/storage/time are bounded, but exact limits, client snapshot, model snapshot, temperature, dispatch order and retry rules are not fully enumerated. A Haiku sweep is omitted from main results for low/noisy success; it is not evidence that the effect generalizes.

**Pass rate is the fraction of a task's hidden tests passing**, not the proportion of complete tasks. Existing unrelated regression tests are not scored after candidate edits (pp. 5, 12). This materially narrows the abstract's completion interpretation. Input/output totals include subagents, combine cached and uncached tokens, and measure cumulative traffic rather than peak context or billed dollars. Reasoning characters overlap output tokens and must not be added again. Revisitation specifically means rereading a previously read-and-edited file; interpreting it as uncertainty is the authors' hypothesis (p. 6).

Trials more than 50% from the median within task/side are removed before averaging, reportedly 9.7%; table captions apply this filter to all cells. The PDF does not fully specify joint versus metric-wise deletion or supply retained denominators/raw values. Equation 1 sums per-task means before taking the percentage difference, giving expensive tasks greater influence on the relative footprint than a mean of task-level percentage effects (p. 6). Repeats are nested in 33 selected tasks and six repositories. No confidence interval, equivalence margin or primary inferential test establishes a null accuracy effect.

## Findings and contrary evidence

Table 2 (p. 6) reports cleaner-side aggregate changes: hidden-test pass fraction -0.9 percentage points, input -7.1%, output -8.5%, reasoning characters -11.1%, messages -7.0%, unique files +3.2%, revisitation -33.8%, edited lines -3.2%. Rounded pass fractions .913 versus .921 yield -0.8 points; the reported -0.9 could reflect unrounded values, which are unavailable. Do not convert either to a task-success count or claim statistical equivalence (p. 7).

Track differences challenge a generic factoring benefit: multi-module tasks have input -10.7% and revisits -50.8%, while hotspot tasks have input +1.8% and unique files +11.2% (p. 7, table 3). Six calibration tasks show zero pass-fraction difference, +3.8% input and -75% revisits; the latter rests on only three rereads in one task and is not a broad effect. Among 27 non-calibration tasks, 16 use fewer and 11 more input tokens on the cleaner variant; effects range -47% to +44% (pp. 8-9). Token effect direction varies within a repository.

The two worked cases distinguish replacing a large dispatcher with grep-targetable helpers (BCEL input -35%) from adding surrounding helper structure without simplifying focal logic (Genie input +8%); relevant files are similar/larger in size on the cleaner side (p. 9, section 4.4). This supports testing change-specific coordination rather than counting abstractions.

Comment normalization uses five repeats per cell versus ten originally and considerable manual editing (p. 10, table 4). Sonar-caas-poc shifts +1.2% to -18.0% input; a LOC-adjusted analysis is mentioned but not specified enough to recreate. Some original deltas in table 4 differ from table 2 (-0.5 versus +1.2 for sonar-caas-poc, -4.7 versus +1.3 for sonar-sca). Do not merge the tables or interpret normalization as an independently randomized pure structural effect. The paper itself declines a stronger effect claim.

## Limits and ALF consequence

The authors acknowledge end-to-end curation, one model/harness, token/dollar distinction, hidden-task tests only, no output-cleanliness scan and one-task horizons (p. 12). Their statement that pooling hundreds of trials makes the aggregate hold is not a substitute for cluster-aware uncertainty, especially after filtering resource-heavy trajectories. Private source reduces one exposure route but does not certify absence of all contamination.

**Correct** any prior description of this paper's pass rate as all-or-nothing task completion or retained regression safety. **Retain** behaviorally checked alternative predecessors, shared task requirements and insensitive/adverse controls as reusable methods. **Narrow** the ALF contribution to prospective change-specific predictions plus inherited obligation outcomes; code-organization manipulation and hotspot task selection already exist. Preserve every ALF assigned attempt rather than importing the median filter, retain both new and prior obligations, distinguish source size from navigation, and do not infer a general F#/Nu effect or latent understanding from lower rereading.
