## Construction and unit of evidence

The benchmark derives Godot4 tasks from public video/web tutorials with permissively licensed repositories. Screening102 video candidates yields57; ranking99 web candidates yields31, for88 tutorials. The paper reports202 initially generated tasks, a41-task human pilot, then154 core tasks plus179 variants: **333 tasks,131 easy and202 hard**. Its stated1.3 generated tasks per tutorial does not follow from202/88 (about2.30); the applicable denominator is unclear. Variants can change animation-frame requirements. Tasks are therefore neither333 independent games nor a representative distribution of professional maintenance changes.

GPT-5-Codex prepares task instructions, starter/solution projects and deterministic validators. The pilot reports43% issue-free,50% minor and7% major issues; automated checks and eight human annotators, five with game experience, refine the set. Annotators may use coding agents and inspect tests to diagnose a failed calibration. This is benchmark construction access, distinct from final solver access. The guide allows5–15 minutes for fixes before escalation/skipping; the main text's roughlyten-minute validation statement is not a total dataset-construction budget.

The tasks intentionally emphasize multimodal assets and scene configuration. Table3's mean114.1 changed lines includes92.2 scene-file lines versus14.9 GDScript lines; medians are48.5 total,24 scene and **zero script lines**. Mean4.7 edited files is useful implementation-burden evidence, but neither quantity establishes equivalent semantic complexity or an advantage of smaller source/context. Gold edits are not all valid possible implementations.

## Intervention, feedback and scoring

The baseline already receives the Godot executable and permission to use images/videos. The video condition adds concrete runtime/movie commands and encouragement to inspect outputs. The screenshot condition adds an editor MCP tool and usage guidance. These are tool/prompt bundles; the comparison does not isolate visual perception from command knowledge, nor prove that baseline agents lack visual access. Editor screenshots expose scene hierarchy/layout; runtime captures expose the camera/game. Reported agents commonly extract video frames using Python, which differs from direct video-model ingestion.

Success is a deterministic Godot assertion result for a task. The construction process requires a passing reference and failing starter, with instructions to permit alternatives. Validators can inspect nodes, properties, assets, scripts and state/physics behavior; passing is not automatically an independent end-to-end temporal observation. Some instructions explicitly require particular APIs, paths or node structures. The paper does not supply an independent valid-implementation/mutant calibration comparable to all of S125's stated checks.

AppendixC's human-validation instructions prohibit reading tests, answer-bearing configuration and files outside the task. Those specific prohibitions do not appear in AppendixD's published solver prompt. Released source below establishes filtered workspaces and post-solver testing at a July pin; stronger September confinement cannot retroactively establish the original agents' access boundary. No leakage is inferred merely from an omitted prompt sentence.

## Consequence for the survey

**Established contribution:** a sizeable tutorial-derived game-engine task set, deterministic scene/state assertions, and measured benefits/costs of simple visual-feedback guidance. Negative and mixed outcomes qualify the method's scope without erasing it. Game implementation involves structured assets and host/editor integration as well as scripts.

**Nu transfer:** this is direct prior work for coding-agent feedback and executable game tasks, not evidence for Nu's architecture, functional state, source compactness, safe live evolution or explicit-case enumeration versus catch-all. The valuable distinction is between permitted development observation, implementation-specific checks, independent temporal obligations and final scoring. A benchmark pass rate cannot substitute for those contracts.

**Next consequential action:** S227's acquired continual-playtesting paper can resolve how GUI-driven evaluation and shared repair memory change observation, judge dependence and retained behavior. S228's recorded OpenGameEval route can add an industrial edit/play and client/server temporal comparison. C05's remaining supplied abstracts and S125's original result/calibration packet remain separate discovery/artifact frontiers. These are evidence tasks, with no authorization for model or candidate execution.
