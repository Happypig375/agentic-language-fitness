## Evidence reconstructed from accessible prose

**What is reproducible.** Pure Arrowised FRP separates signal processing from external effects and time sampling. Replaying the same initial state, input samples and sampling times on the assumed architecture can reproduce the pure computation. Identical user input alone is insufficient: the force-directed-layout example changes with sampling and floating-point calculation. The claimed reliable reproduction excludes bugs in the input/output layer. A functional language name, persistent data structure or visual history alone does not discharge these conditions.

**Temporal testing is bounded.** The conceptual time domain is continuous and unbounded, while executable tests use finite, sampled streams. The prose explicitly makes `Imminently` and `After` true when they refer outside the observed domain, choosing absence of a demonstrated failure over a three-valued unknown. This is a test convention, not evidence about the unobserved future. Sampling can both miss faults and produce behavior different from a continuous model. Live assertions use causal past-time predicates; future-looking assertions require a completed trace or a different evaluation policy. Exact evaluator equations remain to inspect.

**Generators define the evidence.** Stream generators vary values, delta-time distributions, bounds and lengths, with composition and clipping facilities. A short or favorable stream can pass when a longer or differently sampled one fails. The paper demonstrates a bouncing-ball failure after expanding QuickCheck limits and a Haskanoid failure after 3,443 tests in a displayed run. These are author-reported counterexamples, not sensitivity estimates, a task population, or an independent testing benchmark. Real user traces can be prefixed to generated continuations; the authors explicitly reject expecting low-level random generators to faithfully produce long, realistic gameplay sessions.

**Replay is an implemented tool bundle.** An extended execution loop records inputs and times, accepts commands and communicates with an external GUI through two sockets. The tool supports navigation, assertions, replacement inputs and re-running changed code against a trace. The related-work prose describes retained intermediate signal functions for constant-time navigation; the conclusion separately describes arbitrary-start snapshot recording as future work. Do not conflate navigation in retained execution state with exporting a restorable snapshot of a complete external system.

**Effects require additional contracts.** Software/hardware-in-the-loop examples need correctly implemented communication and a reset operation that restores the external component before each test. The language does not capture a general reset guarantee. Without reset, a reported counterexample or shrinking sequence can fail to reproduce. The Arduino example tests a restricted positive-number domain; its simplified representation and reset assumptions do not establish arbitrary hardware correctness.

**Fault modeling is conditional.** A satellite example injects faults using specified rates and a random seed, then exercises redundant sensing. It shares a clock between simulated physics and control, so changing the clock alters both simulation accuracy and control frequency. The authors acknowledge that this does not isolate which source is responsible. The fault seed is not exposed for effective shrinking; coverage and improved shrinking remain open. This is not independent evidence that Nu's architecture is robust or that testing proves a fault-tolerance guarantee.

**Game experience has limits.** Haskanoid is a Breakout implementation; the demonstrated physics/invariant version is simplified relative to the full game's levels, lives and sound. The paper describes finding tunneling and uncapped-velocity cases; the ad hoc cap is explicitly not a reusable general solution. Commercial-game use is also reported, with a disclosure that mobile extensions and that use were developed by the first author's company. There is no controlled human/agent comparison, representative defect denominator, net-effort estimate or independent commercial evaluation in the accessible account.

## Consequential adverse cases

The conclusion explicitly leaves performance costs and instrumentation effects unstudied. Recording can change the sampling regime so that a fault ceases to appear; reducing instrumentation to input logging is a mitigation, not proof that overhead is harmless. It also notes that a user-interface change can invalidate recorded low-level input, limiting replay across edits. Recording higher-level actions is proposed as a possible improvement.

Starting from an arbitrary snapshot can discard past information needed by temporal properties. The paper also leaves input-space coverage, trace shrinking, comparison with other temporal logics and distributed-system adaptations unresolved. These are concrete boundaries on a Nu proposal: resource costs, historical obligations, trace compatibility and external effects cannot be assumed solved by immutable state.

## Three criteria and next decision

**Unique:** broad invention claims for functional game replay or temporal property testing are already untenable. S46/S47 supply close predecessor mechanisms and a direct Breakout lineage. Any retained Nu question must identify its particular convention, mechanism and measurable outcome; D1 priority remains unconfirmed.

**Valuable:** reproducible failures and explicit temporal obligations are plausible benefits. The source offers demonstrations and experience, not measured comparative Nu or coding-agent benefit. Net cost, real task prevalence and transfer to mixed-effect engines remain unmeasured.

**Scientifically valid:** distinguish a finite trace passing from satisfying an unobserved future obligation; expose unknown or truncated observations; freeze sampling, trace length, input generation and effect/reset boundaries. Verify old/new trace meaning after an edit. Record instrumentation and restoration costs. A snapshot must include or explicitly exclude external resources and relevant history. These are design implications, not authorization to build apparatus.

Remaining source work is precise: obtain and inspect the paper's displayed temporal definitions/evaluator, seven figures, missing code and bibliography before marking a complete reading.
