Keep Codex `0.149.1`, image `sha256:5d3e97d195dbbe7e47e47055e46f8c6f15fb9553be0c7ef19ed0060756fc7116`, Luna/high, and the fixed model catalogue, context, and settings across each pair. No API key, general Platform bearer OAuth, proxy, daemon, provider relay, backend matrix, extra `CODEX_HOME` synchronizer, secret relay, or production remote RPC may be introduced.

The candidate authority remains strict full-source JSON file replacement. Before execution, a supported pinned CLI configuration must demonstrate that candidate shell, file, tool, subagent, browser, and MCP dispatch are unavailable; there must be no tool results, and the candidate must not access auth, research, gold, user/system configuration files, or successor/holdout material. Frozen CLI scaffold metadata is allowed and recorded separately as Codex scaffold, not treated as raw API equivalence. A synthetic hostile tool-call fixture must be blocked before side effects and provider follow-up. If no supported no-tools configuration exists, the proposal is held; there is no toolful fallback or custom filtering proxy. The candidate remains blind to AGENTS/PLAN governance text, hypotheses and research outcomes, successors, future tasks, target gold, and holdouts; the approved current and cumulative prior contracts, predecessor, and later bounded source/reply/feedback entries are supplied only as specified below, with fixed candidate instructions.

### Memory and replay (proposed scientific change)

Replace the unfrozen provider-response-chain assumption with deterministic **visible-transcript replay** in a fresh `--ephemeral` CLI session for every submission. A session must not import prior rollouts, memory, plugins, or auto-summaries. Do not use `exec resume`, `previous_response_id`, retained hidden reasoning, provider continuation, automatic memory, compaction, or follow-up requests. Build one canonical UTF-8 JSON replay document with deterministic key/file ordering: immutable candidate instructions once, then chronological labelled `user`/`assistant` entries containing the initial contracts/predecessor, each prior raw reply, and each repair's current source plus deterministic feedback; the final entry is the next repair input. These role labels are data inside one new CLI user message, not a promise that the provider receives historical roles. Preserve underlying content strings without model or human cleanup, and count complete encoded stdin—including JSON escapes and framing—against the authored 131,072-byte cap. Do not duplicate instructions or the current repair entry. This replay is not equivalent to a provider chain and must not be pooled with the API proposal or historical Codex treatments. A failed terminal submission never receives credit from an older source. Native compaction/truncation is disabled; a provider context-limit rejection is retained as a failed attempt and stops the batch without reissue.

### Limits and accounting (proposed scientific change)

Retain Tasks 001, 006, and 007, four pairs each, 24 trajectories, and at most three submission-turn dispatches per trajectory. The pilot ceiling is therefore 72 **dispatches**, explicitly not 72 provider generations. A separately approved integration may use at most two dispatches on an unrelated task and is distinct from the historical two-generation/$0.05 API proposal.

The byte phase matters. A complete captured assistant final reply over 49,152 bytes, with reliable terminal usage, consumes that dispatch and is a `terminal-submission-byte-budget-exhausted` outcome: it is format-invalid, is not applied, built, repaired, or scored as an older workspace, while raw bytes, known usage, and any earlier first score remain; terminate only that trajectory and continue scheduled others unless an independent alarm or ambiguity stops the batch. A complete replay document over 131,072 bytes is `trajectory-input-byte-budget-exhausted` before launch: no submission is consumed and no new dispatch, feedback, retry, summarization, truncation, or slot replacement occurs; preserve actual first/last outcomes and assigned slots. If the initial payload cannot fit for all fixed slots, report apparatus/preflight failure before candidate calls rather than dropping a language. An in-run replay overflow is a resource outcome, not exclusion. Outputs under 49,152 bytes, including malformed outputs, remain repairable under the existing budget; safe project errors remain governed by R2. Incomplete/aborted capture or unknown usage remains the separate ambiguous batch stop described above.

Also retain 120 seconds per CLI request lifecycle, 600 seconds per trajectory, 60/10/10-second build/development/holdout limits, 1 MiB raw controller capture, 8 source files, and 8,192 feedback bytes. Retain only bounded capture plus an overflow flag; never claim bytes beyond the cap were retained. An incomplete or aborted capture is ambiguous, stops the batch, and is never accepted as a replay or silently trimmed patch. A CLI turn is not assumed to equal one provider request. Request count is observed when reliable, otherwise null; ancillary auth/catalog HTTP is separate and unknown counts remain null. Cache and reasoning fields remain subsets and are never added twice; CLI zeros for absent optional fields are normalized to null as unproven while raw output is retained. Field presence alone is not provenance. Missing usage remains null while known outcomes remain. Non-generation OAuth refresh is permitted, but automatic generation replay/relaunch after error or ambiguity is not. Intended OAuth internal generation retries must be verified disabled; a custom fixture configured for zero retries does not prove the builtin setting. Any unexpected provider follow-up, wrapper retry, or ambiguous charge is retained and stops further dispatch. No claim is made about a hard provider token, request, dollar, or subscription-allowance upper bound. The maintainer must explicitly accept overshoot and that limitation before any live OAuth use; otherwise hold. The old $0.05/$2 envelopes remain historical API proposals, not OAuth guarantees.

R1–R3 remain in force: task 007 still requires its architecture rubric and unknown missing evidence; safe F# Compile-list mistakes remain repairable while unsafe project changes are terminal; and intact feedback overflow terminates only that trajectory. R4's no-silent-generation-retry, ambiguity-retention, and unknown-telemetry principles are preserved, but its literal pre-count/dollar-reservation mechanism is replaced by the replay and post-turn resource controls above as an explicit review decision. Tasks, models, samples, source identities, and analysis claims remain unchanged; no causal or universal language ranking is implied.
