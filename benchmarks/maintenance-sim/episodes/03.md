# Episode 03 — follower interaction

Add `spawn_follower` (`id`,`target`,`x`). Duplicate-ID validation precedes
target lookup; a missing target is `missing_entity`. A follower has wire fields
`kind:"follower"`, `id`, `x`, `velocity:0`, and `target:string|null`; movers
retain seed shape. On every tick movers advance first. Followers then update
simultaneously from the post-mover/pre-follower snapshot by the sign of
`target.x - self.x` (one unit toward target; equal means no move). Chains are
therefore deterministic. Removing a target sets followers' target to null and
reuse never silently reattaches. Save/load preserves kinds and targets.

`x` uses the spawn coordinate bounds; `id` and `target` use the seed ID grammar.
Shape/value checks precede duplicate and missing-target checks. Success emits
`spawn:<id>`. A null target stays still. Compare positions to determine direction
without overflowing a subtraction at signed-64-bit extremes. Adding or
subtracting the one-unit step remains checked. Same-tick deferred spawns/removes
run before both movement phases. Deferred commands remain only spawn/remove.

## Public example

Input: `{"version":1,"operations":[{"op":"spawn","id":"a","x":0,"velocity":1},{"op":"spawn_follower","id":"b","target":"a","x":3},{"op":"tick","count":1}]}`

Output: `{"version":1,"state":{"tick":1,"entities":[{"id":"a","x":1,"velocity":1},{"kind":"follower","id":"b","x":2,"velocity":0,"target":"a"}]},"effects":["spawn:a","spawn:b","tick:1"],"errors":[],"snapshots":[]}`
