# Episode 01 — deferred commands

Add `enqueue` (`at`,`sequence`,`command`) where `at` is strictly greater than
the current tick and at most 1,000,000, `sequence` is non-negative signed 64-bit,
and command is a fully shaped/domain-valid `spawn` or `remove`. Shape, ID,
range, and command-field errors occur at enqueue; duplicate IDs and missing
entities are checked only when due. A successful enqueue emits
`enqueue:<at>:<sequence>`.

Each outer tick increments the clock one at a time. It extracts the whole due
batch, sorted by `(at, sequence, enqueue-order)`, executes commands, then moves
all entities, then proceeds to the next tick. Inner errors append normal errors,
are atomic for that inner command, and do not abort the batch. The outer
`tick:<count>` effect is last. Overflow anywhere in the entire outer operation
rolls back state, queue, effects, and inner errors, emitting only `overflow`.
Saved state carries pending commands internally; seed response snapshots stay
unchanged. Preserve seed behavior. Enqueue order is a monotonically increasing
ordinal among commands admitted into the current world; save/load restores its
ordering effect. Use ordinal order only to resolve equal at/sequence entries.
If the next required ordinal exceeds signed 64-bit, enqueue fails atomically
with `overflow`. Empty pending work may restart the ordinal at zero; drained
history is not observable.
Malformed nested commands use the seed operation errors, including
`unknown_operation`; valid but unsupported nested operations yield
`invalid_value`. Never consult current entity existence during enqueue.
An operation is recognized only after its public introduction. For a recognized
but unsupported nested operation, check its immediate required/extra fields and
their JSON types first (`invalid_shape` on failure), then return `invalid_value`.
Do not execute it, inspect its nested payload's semantics or resolve world-state
references. The full shape/domain validation above applies to the supported
`spawn` and `remove` commands. Unknown names remain `unknown_operation`.

## Public example

Input: `{"version":1,"operations":[{"op":"enqueue","at":2,"sequence":9,"command":{"op":"spawn","id":"z","x":0,"velocity":0}},{"op":"enqueue","at":1,"sequence":4,"command":{"op":"spawn","id":"b","x":0,"velocity":0}},{"op":"enqueue","at":1,"sequence":2,"command":{"op":"spawn","id":"a","x":0,"velocity":0}},{"op":"tick","count":2}]}`

Output: `{"version":1,"state":{"tick":2,"entities":[{"id":"a","x":0,"velocity":0},{"id":"b","x":0,"velocity":0},{"id":"z","x":0,"velocity":0}]},"effects":["enqueue:2:9","enqueue:1:4","enqueue:1:2","spawn:a","spawn:b","spawn:z","tick:2"],"errors":[],"snapshots":[]}`
