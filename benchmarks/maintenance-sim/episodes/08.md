# Episode 08 — replay

Add `replay` (`snapshot`,`events`) using a temporary world initialized from the
named saved snapshot and a copy of the current named-snapshot registry. Events are processed
in listed order, with at most 256 events, using every prior operation rule.
Nested replay is `invalid_value`. Any temporary error aborts the whole replay,
appends the first error to the outer errors, emits no replay effect, and leaves
the outer world/logs/snapshots unchanged. Success commits only the temporary
final live world, discards temporary effects/errors and snapshot-registry
mutations, leaves the original named snapshots unchanged, and emits
`replay:<name>`.

For example, request/cancel/complete in replay fails on stale completion and
has no replay effect. Preserve all cumulative obligations and distinguish
prerequisite failure from current replay correctness.

`snapshot` uses the snapshot-name grammar and must exist (`missing_snapshot`
otherwise). `events` must be an array of at most 256 operations; bad type or
length yields `invalid_shape`. Empty replay succeeds. Any valid-shaped nested
replay is forbidden even if its inner list is empty. The outer error appended
on abort is the first temporary error in execution order; earlier outer logs
stay intact. A save/import within replay affects subsequent temporary load
operations only; it never changes the outer named-snapshot registry.

## Public example

Input: `{"version":1,"operations":[{"op":"spawn","id":"a","x":0,"velocity":1},{"op":"save","name":"s"},{"op":"replay","snapshot":"s","events":[{"op":"tick","count":2}]}]}`

Output: `{"version":1,"state":{"tick":2,"entities":[{"id":"a","x":2,"velocity":1}]},"effects":["spawn:a","save:s","replay:s"],"errors":[],"snapshots":[{"name":"s","data":{"version":2,"tick":0,"entities":[{"kind":"mover","id":"a","x":0,"velocity":1}],"pending":[],"policies":[],"requests":[],"issued":[]}}]}`
