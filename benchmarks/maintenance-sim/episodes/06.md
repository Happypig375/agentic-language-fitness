# Episode 06 — deterministic asynchronous input events

Add `request` (`id`,`sequence`), `cancel` (`id`,`sequence`), and
`complete` (`id`,`sequence`,`value`) as input events. The ID must be an existing
entity when requesting; sequence is non-negative signed 64-bit and value is an
integer in the coordinate domain. One outstanding request per ID is allowed:
no previous issued sequence for the ID, or a sequence strictly greater than its
last issued sequence, succeeds and replaces any outstanding request; otherwise
`invalid_value`. Success emits `request:<id>:<sequence>`.

Cancel matches the pending sequence or yields `invalid_value`; success emits
`cancel:<id>`. Complete matches or yields `stale_completion`; success emits
`complete:<id>:<value>` and clears pending without changing x. Remove clears
outstanding work but retains a last-issued sequence ledger across reuse.
Snapshots sort pending requests and issued `{id,sequence}` ledger; absent
fields in imported v2 default empty. All operations are deterministic and
service/thread/clock/network-free.

The v2 fields are `requests` and `issued`, each an array of exactly
`{id,sequence}` entries, unique by ID and sorted by ordinal ID. Requests refer
to live entities; issued entries may outlive a removed entity. Each request must
have a matching issued entry with equal sequence. Missing referenced entities
yield `missing_entity`; missing/mismatched ledger entries, duplicate IDs or
negative sequences yield `invalid_value`. Missing fields on earlier v2 imports
default independently to []; inconsistent combinations are rejected. Save/load
restores both arrays as world state, including the issued ledger. Legacy v1
retains its exact tick/entities shape and initializes both arrays empty.
Values on complete use spawn x bounds;
successful cancel/complete never erase the issued ledger. Standard shape/value
validation comes before state lookup. Cancel/complete with no matching pending
request produces its specified error even if that entity no longer exists.

## Public example

Input: `{"version":1,"operations":[{"op":"spawn","id":"a","x":0,"velocity":0},{"op":"request","id":"a","sequence":1},{"op":"cancel","id":"a","sequence":1},{"op":"complete","id":"a","sequence":1,"value":7}]}`

Output: `{"version":1,"state":{"tick":0,"entities":[{"id":"a","x":0,"velocity":0}]},"effects":["spawn:a","request:a:1","cancel:a"],"errors":["stale_completion"],"snapshots":[]}`
