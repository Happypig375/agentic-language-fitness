# Episode 07 — quiescent batched fast-forward

Add `fast_forward` (`count`) for count 1..1,000,000,000. It is quiescent only
when every entity is a mover, none has an assigned policy, the deferred queue
is empty, and no request is outstanding. Unused registered policies and the
issued-sequence ledger do not prevent quiescence. Non-quiescent requests are
atomic `nonquiescent` errors. In the quiescent case, exact multiplication
and addition compute the same final state as repeated ticks, with one
`fast_forward:<count>` effect; effect strings need not match repeated ticks.
Work must be bounded by entity count, not count. No wall-time ceiling or
relative-language performance claim is part of this contract.

Range-check the resulting tick and positions against signed 64-bit. Wider
intermediates from the standard library are allowed: an intermediate product
outside that range is not itself an overflow when the final position fits.
For example, x = -9223372036854775807 and velocity = 9223372036854775807
can advance twice to x = 9223372036854775807 without overflowing either tick's
position. A naive checked 64-bit product would reject this valid evolution.

## Public example

Input: `{"version":1,"operations":[{"op":"spawn","id":"a","x":2,"velocity":3},{"op":"fast_forward","count":1000000000}]}`

Output: `{"version":1,"state":{"tick":1000000000,"entities":[{"id":"a","x":3000000002,"velocity":3}]},"effects":["spawn:a","fast_forward:1000000000"],"errors":[],"snapshots":[]}`
